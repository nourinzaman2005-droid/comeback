# Render, PostgreSQL, Groq, and GitHub Pages setup

The repository is ready to deploy without putting a database password or Groq
key in Git. Render creates the API and PostgreSQL database from `render.yaml`.

## 1. Create the Render backend

1. Sign in to Render and open
   `https://render.com/deploy?repo=https://github.com/nourinzaman2005-droid/comeback`.
2. Choose **Create Blueprint** and confirm the `comeback-api-nourin` web service
   and `comeback-postgres` database.
3. When Render asks for `GROQ_API_KEY`, paste the free Groq key. Leave it blank
   if the key is not ready yet. The safe cited fallback still works.
4. Wait for the web service deploy to finish. Do not manually add
   `DATABASE_URL`: the Blueprint connects it to PostgreSQL automatically.
5. Open `https://comeback-api-nourin.onrender.com/health`. The expected response
   is `{"ok":true,"database":"postgres"}`.

If Render assigns another web-service URL, replace
`https://comeback-api-nourin.onrender.com` in `.github/workflows/pages.yml` with
the actual URL and push that change. GitHub Pages embeds this public API URL at
build time.

## 2. Check Render environment variables

Open the web service, then **Environment**. Confirm:

- `DATABASE_URL` is linked from `comeback-postgres`;
- `SESSION_SECRET` was generated by Render;
- `FRONTEND_ORIGIN` is `https://nourinzaman2005-droid.github.io`;
- `DEMO_MODE` is `true` for the hackathon demo;
- `GROQ_API_KEY` is present if generated explanations are required.

Never paste these values into GitHub, chat, screenshots, or `.env.example`.
After changing a Render environment variable, use **Save and deploy**.

## 3. Deploy the frontend

1. In GitHub, open the repository's **Settings**, then **Pages**.
2. Set the source to **GitHub Actions**.
3. Push the final code to `main`, or run the **Deploy GitHub Pages** workflow
   manually from the **Actions** tab.
4. Open `https://nourinzaman2005-droid.github.io/comeback/` after the workflow
   succeeds.

## 4. Verify the live end-to-end flow

1. Register a new player with a unique email and choose Dr. Maya Rahman.
2. Complete a movement check-in and save the symptom screen.
3. In a private browser window or second device, open `/comeback/clinician/`.
4. Use the fictional clinician demo account:
   `maya.rahman@icc-demo.org` / `CareTeam2026!`.
5. Select the new player, inspect the saved observation, and send a chat reply.
6. Approve a symptom-free check-in, or confirm approval is disabled when a
   symptom is reported.
7. Return to the player session and verify the stage, notification, and message.
8. Ask the explanation panel a question. With Groq configured it should return
   validated cited JSON; without Groq it should return the deterministic cited
   fallback.

## 5. Local Groq testing

`.env.local` is ignored by Git. Add the key only on your own machine:

```dotenv
GROQ_API_KEY=your-real-free-groq-key
```

Then restart `npm run dev`. Do not commit `.env.local`.

## Free-tier limitation

Render currently expires free PostgreSQL databases after 30 days and provides
no free-plan backups. Use fictional demonstration data only, and recreate or
upgrade the database before the deadline if the demo must remain online.
